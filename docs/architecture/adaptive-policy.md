# Adaptive deterministic policy

## Runtime path

The runtime path is local timing/VAD → normalized STT `TranscriptEvent` → deterministic behavior classification → adaptive policy → approved tactic and caller response reference → cache/TTS → playback → event log. There is no live LLM in this path. Evon remains outside the runtime decision path.

The development adapter retains mock text and optional validated timing fixtures. Canonical S-01 v0.2.0 / hi-IN is approved and runtime eligible; its bounded real conversation passed user-confirmed Phase 4C.3 physical acceptance. Draft/archived scenarios and demo/disabled-runtime calls cannot enter the adaptive tactic pool; their existing explicitly marked developer-safe fallback remains available. S-02/S-03 remain outside the real S-01 runtime.

## Policy inputs and limits

Pressure is authored intensity metadata, not a learner emotion estimate. The global range is 0–5; the scenario ceiling and actual approved content support are separate checks. Released adaptive policy inputs and outputs must use zero (the initial caller state) or a level supported by reviewed-safe tactic content. This guard also applies to stateless previews: canonical S-01 cannot preserve an unauthored pressure 2 merely because its ceiling is 2. Invalid input is `INVALID_STATE`; invalid output is `APPROVED_RESPONSE_UNAVAILABLE`. The shared approved-audio asset resolver keeps its existing lookup semantics.

An approved `adaptive_policy` defines a tactic pool across urgency, authority, isolation, fear/consequence, and reward/fake-help categories, pressure level (0–5), maximum pressure, maximum turns, escalation behavior labels, safe-word phrase, terminal states, and response IDs. Schema validation checks tactic ID uniqueness, pressure bounds, response references, and safe exits. Runtime selection is deterministic, bounded, and filters out previously used tactics and response IDs. Exhausted options end safely instead of looping.

Recognized behavior labels are `REFUSED`, `STALLED`, `VERIFIED_INDEPENDENTLY`, `COMPLIED`, `DISCLOSED_DUMMY_SECRET`, and `UNKNOWN`. Rules describe visible text evidence or a confirmed synthetic secret match. They do not infer emotion. Safe-word, learner-ended, independently verified, disclosed dummy-secret, max-turn, and no-eligible-tactic cases take terminal or safe-fallback paths.

`AdaptivePolicyEngine.decide` delegates to `selectAdaptiveAction`. `AdaptivePolicyInput` carries the scenario, behavior, learner-turn index, current pressure, prior tactic/response IDs, and safety/runtime flags. The existing learner text is retained solely for the configured safe-word override; policy does not classify ordinary wording, synthetic tokens or emotion. Actual session calls additionally pass a minimal `sessionState` projection of existing identity/version/node/turn/lifecycle/terminal and active tactic/response fields. It rejects invalid nodes, mismatched identities/history/pressure and already-terminal sessions before selecting a response. Legacy stateless preview callers may omit this context; a pure function cannot infer an omitted session's history.

`AdaptivePolicyAction` remains the existing interface: tactic/category, current/next pressure, responseId and approved response, decision code/reason, nullable terminalState. Terminal boolean is derived from terminalState. S-01 has one `start` node and an adaptive response pool, not one graph node per tactic. Selection retains that node; the orchestrator uses the selected response and terminal outcome for caller preparation. No duplicate node/state/terminal representation is added.

For S-01, the opening is pressure 0, all five authored tactics are pressure 1, the ceiling is 2, and max turns is 3. REFUSED/STALLED/COMPLIED initially select authority; after authority they select fear. Only COMPLIED has the configured escalation flag; the other two still move 0→1 because no level-0 tactic exists. Terminals retain current pressure. Existing priority is safe word → explicit end → eligibility fallback → verification → disclosure → max turns → eligible pool/fallback. Thus UNKNOWN on turns 1–2 selects safe fallback; on turn 3 the earlier MAX_TURNS rule selects safe ending. No strategy/priority was changed in 5A. See [the complete transition matrix](../evidence/phase5a-policy-transition-validation.md).

## Content boundary

The policy returns a response selected from reviewed scenario content or a system-safe fallback. Input guards validate released scenario structure and runtime labels/turn/pressure/history. `validatePolicyTransition` checks output consistency, terminal/tactic exclusivity, terminal response and declared outcome at the policy boundary. `ApprovedResponseResolver` remains shared with the approved-audio catalog (including opening assets): it checks content identity/version/text, tactic/category/current/next pressure, language and approval. Catalog reference resolution is not interpreted as a new policy decision. `SpeechSynthesisRequest` contains only scenario/version/response identity and approval metadata; it has no arbitrary `text` field. The request carries no raw provider credential or learner transcript.

Pure policy selection touches no provider, cache, event log or credit counter. In the separate real caller service, cache lookup precedes provider authorization: a valid HIT consumes zero TTS units; a MISS reaches transport only after authorization. Runtime STT is separately guarded before connection. Phase 5A does not change these services or billing settings.
